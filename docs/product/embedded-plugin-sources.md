# 划词：嵌入式开源复用

划词使用 DingDong 界面并选择性复用原生选区代码，在插件中注明来源。截图仅转发到系统工具，见[系统截图快捷键](screenshot-plugin.md)。

## 实现边界

- 划词：选择性适配 `selection-hook` 的 Windows 原生选区读取代码，在独立 COM 工作线程运行；DingDong 负责鼠标/键盘触发、浮条、结果面板、模型请求与配置。主进程管理密钥，子窗口参数不包含密钥或选中文字。
- 默认关闭；仅在主动点击模型动作或追问时发送文字。自动选区读取不模拟复制，不改动剪贴板。密码框及无法读取选区的程序不弹浮条。
- 截图/划词属于 DingDong 自己的插件。其他 Agent 客户端的插件仍放在“资源 → Agent 插件”，不混入本目录。

## 上游更新

划词详情的“检查上游更新”只向固定的官方 GitHub 元数据接口请求版本，不发送选中文字、配置或密钥。网络失败、限流、元数据错误显示检查失败，不能显示为已是最新。

包版本按数值比较；原生适配以提交基线比较。发现不同提交仅表示上游有变更，不表示变化必然适用。检查不下载或执行新代码。升级由维护者更新固定依赖，或对照保留的上游基线移植相关差异，完成回归后随 DingDong 版本提供。只添加来源注释不能实现自动更新，也不能代替适配验证。

## 验证要求

验证快捷键冲突/停用，截图选区和导出像素，取消与保存失败，浮条出现位置及焦点，密码/无选区排除，过期读取与停用后的消息丢弃，模型请求取消/超时/认证失败，安全存储和原有设置回归。自动测试不能代替浏览器、编辑器、聊天应用、高 DPI/多屏及实际模型服务的人工验收。

## Windows 隐藏窗口的首帧

Flutter 3.44.6 的 Windows 引擎仍包含 [flutter/flutter#187922](https://github.com/flutter/flutter/issues/187922)：窗口调整尺寸时若产生空帧，`OnEmptyFrameGenerated` 会把绘制表面的宽高传反。实际表现为黑色横带、内容压缩，直到下一次有效调整尺寸才恢复；仅等待布局结束后显示窗口不能消除已经损坏的表面。

截图窗口先绘制占满窗口的不透明背景，等待首帧完成栅格化后才初始化并调整原生窗口；读取图片和关闭编辑时也保留背景。对应回归检查非方形窗口的实际背景绘制及原生调用顺序。避免使用连续增减一像素的修补办法，上游记录指出该做法还可能阻塞呈现。
