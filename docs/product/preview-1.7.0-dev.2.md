# DingDong 1.7.0-dev.2 预览验收

DingDong 继续免费开源。本轮围绕“看得懂、开始得了、数据可信、遇到问题有出口”补齐产品流程。

## 产品判断与改动

| 缺口 | 本轮处理 | 验收入口 |
| --- | --- | --- |
| 首次打开没有 Agent 事件，不知道下一步；再次进入接入页，安装指导藏在高级选项里 | 空状态提供接入按钮，安装指导始终显示；高级选项保留命令和端点等技术详情 | 动态 → 接入 Agent |
| 资源库没有内容与搜索不到内容使用同一提示 | 区分空库与筛选无结果；空库提供新建和导入动作 | 资源库 / 资源管理 |
| Token 刷新遇到数据库忙时，本轮报告漏算已经保存的记录；缺失数据可能被理解成零 | 按每个成功提交批次计数，修正不可读和空筛选提示；可停止本次刷新，稍后继续 | 资源管理 → Token 历史 |
| 统计只能看，难以带出去分析 | 导出当前年份、来源筛选的每日 CSV，保留未知、下界及日期可信度信息 | Token 历史 → 导出 |
| “插件”容易被误解为所有 Agent 插件都能在此安装管理 | 将 DingDong 扩展与 Agent 插件分区；提供本机 Codex / Claude Code 插件只读清单、版本、来源、启用状态和读取结果 | 插件 → 读取 Agent 插件 |
| 预览版与正式版比较不正确，后续可能漏报正式版更新 | 修正版本优先级，显示预览版说明和对应发布页 | 设置 → 版本 |

## 为什么这样改

剪贴板、资源复用、跨 Agent 消息收口和使用统计各自都能提供价值。产品需要把“从哪里开始、数据代表什么、下一步怎么做”说明白。当前先沿用熟悉的入口，减少必须理解的概念。

插件是由原生 Agent 管理的能力包，可能包含 Skill、MCP、Hook 等组件；工具是其中提供的具体操作。清单能帮助用户找到来源和归属，但“已安装”“已启用”“已认证”“调用成功”是不同状态。此版不会用一个绿色状态代替所有这些判断，也不会复制宿主管理的插件造成双重配置。

完整插件安装市场、跨宿主权限代理、全量工具调用诊断尚未实现。等不同 Agent 的配置归属与兼容性明确后，再逐步开放适配器的管理动作。

## 本机验收步骤

1. 打开设置 → 版本，确认 `1.7.0-dev.2 (67)` 和预览说明。
2. 打开接入页，确认无需展开高级选项即可找到安装指导。已有接入继续工作。
3. 进入 Token 历史：切换年份与来源、点选一天，检查输入、输出、缓存及不完整提示。刷新时可停止本次刷新；后台定时刷新仍会继续。
4. 导出当前筛选的 CSV，确认只含日期、Agent 来源、数值和完整性说明，不含对话、文件路径或凭据。
5. 打开插件页，主动读取 Agent 插件；缺失或读取失败应有明确提示。清单为只读，管理仍在对应 Agent 中进行。
6. 检查现有剪贴板内容、分类、搜索、资源和通知偏好。新用户空库会看到创建/导入入口；不要为测试清空自己的资料。
7. 设置 → 报告问题可反馈预览问题。注明版本和操作步骤即可，避免附带私人内容。

## 发布与验证边界

- 本次提供 Windows x64 预览安装包，使用既有 DingDong 身份和本地数据目录。
- 稳定版仍是 1.6.2；预览包独立列在 GitHub Prerelease，不更改稳定版更新源。
- Token 统计来自受支持的本地 Codex、Claude Code、Pi 日志，不是平台账单或全系统用量；缓存已计入输入，推理已计入输出，不能重复相加。
- SQLite 只保存统计所需数值及去重标识，不保存会话正文。CSV 导出不联网。
- 插件清单按需读取。没有运行工具来验证认证或实际执行可用性。
- Codex 清单要求可直接执行的原生 CLI；只有 `.cmd` / `.ps1` 包装脚本的安装会显示未发现原生 CLI。Claude Code 支持 `CLAUDE_CONFIG_DIR`，项目级启用状态可能未知；一方读取失败不会隐藏另一方结果。
- Widget 图使用合成数据；原生 Windows 点击流程与手机通知到达由本机验收补充，不能以单元测试代替。
